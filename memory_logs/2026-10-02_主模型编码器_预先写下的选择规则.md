# 主模型用哪个编码器，预先写下的选择规则

## 为什么要先写
两个编码器各有一半好处。原编码器（空间分支池化成一个向量）下，落点门控七次运行都排第一，落点干预三个种子都让它从第一掉到最后，但落点 top-1（15.0% 到 15.3%）没超过规则基线（15.8%）。保留分辨率的编码器（逐格输出落点）下，种子 0 的落点 top-1 是 21.5%，但落点门控只排第 4。论文的主模型只能有一个，不能两头各取好看的那一半。第三视角会话 17:00 建议在结果出来前把规则定下。

## 规则
保留分辨率的编码器当主模型，要同时满足下面三条。
1. 落点成绩。三个种子的落点 top-1 都高于 15.8%（202 场），并且三个种子的均值至少 19%。
2. 落点干预。它的落点干预运行里，落点门控比同种子基准下降至少 0.20，并且落点的门控名次掉到最后两名。今晚只有种子 0 的干预；种子 0 不满足就直接判不满足，种子 0 满足的话再补种子 1、2，三个都满足才算过。
3. 门控图景稳定。三个种子里，门控均值排前三的任务集合至少有两个任务相同，并且落点的门控名次在三个种子之间相差不超过 2。

三条有任何一条不满足，主模型就用原编码器，保留分辨率的编码器只作为补充结果，说明“落点任务换一个保留分辨率的结构能做到多好”，不拿它的门控做任何主张。

## 两种结局下论文怎么写（先写下，免得事后挑）
- 用原编码器当主模型时，如实写落点 top-1 没超过规则基线、只有对数损失更好，并把保留分辨率编码器的成绩和它的门控形态不同这两件事都报出来。
- 用保留分辨率的编码器当主模型时，“落点门控最高”这句话不再能写，门控的证据改成它自己的干预结果和它的门控排序对单任务增益的相关，原编码器的结果作为对照报出来。

### 这次干预里还看到的一件事，如实记下
保留分辨率的编码器在落点的空间输入被打乱后，不是把落点的门关上，而是整个共享的空间编码器塌了。证据有三条。一，测试时打乱空间张量，八个任务的指标下降量全部是 0（基准运行里 Interception 是 0.091，Tackle 0.104，Pressure 0.078）。二，其余七个任务的成绩一起掉到只用标量的水平，Interception 0.642 到 0.619，Pressure 0.599 到 0.578，Pass 0.911 到 0.908，Tackle 0.608 到 0.604。三，直接看空间特征图，2000 个真实传球事件之间的标准差平均只有 0.025（基准运行是 0.647），绝对值平均 0.92，也就是输出饱和成了几乎不随输入变的常数。
也就是在这个结构里，一个任务的空间输入变成噪声，受损的是所有任务，门控没有起到把噪声隔在该任务之内的作用。原编码器下不是这样，落点干预的三个种子里其他任务的成绩变化都在 0.013 以内。这是对保留分辨率编码器加门控这个组合不利的结果，写论文时如果提到这个变体，要一并写。只有一个种子。
